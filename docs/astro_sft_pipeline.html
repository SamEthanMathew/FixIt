Text-FixIt · Stage 2

ASTRO for Text-FixIt

Teaching an 8B model to search for a physical repair by showing it searches that failed first — and recovered. It worked: 6.7% → 78.1% on fully held-out shapes.

Method: arXiv:2507.00417 (AI at Meta) Target: Qwen3-VL-8B, LoRA r=16 Trained + evaluated: 2026-08-18/19 945 eval episodes
01 — The shape of it

Input, process, output

Before any of the paper's machinery, this is all the pipeline does.

Input

A broken refrigerator, in simulation.

  • 43 PartNet-Mobility fridges, split by shape
  • one part given one wrong transform
  • the healthy URDF, hidden, as reference
  • PyBullet as the verifier
Process

Search the repair space, then tell the story of the search.

  • score every candidate repair in the simulator
  • keep the tree, failures included
  • flatten it into one search that fails, backtracks, and succeeds
  • replay it through the real environment
Output

Supervision, and an adapter.

  • ~16k pairs of (prompt → think · backtrack · act)
  • a LoRA adapter over the language tower
  • vision tower untouched

The model never sees the answer. It has to measure its way to the repair — each action is applied fresh to the broken object and the simulator reports how many millimetres of error remain. So the thing worth teaching is not the answer. It is the procedure.

02 — The original

What ASTRO does

ASTRO's claim: Llama-3 fails under RL because it has no search prior — it never reflects or backtracks, so RL has nothing to amplify. The fix is to build that prior by hand, from a search tree, before RL ever starts.

Then supervised fine-tuning on those traces, and RL after. The result that justifies the whole approach is ASTRO's own controlled ablation: same problems, same trees, same number of examples — the only difference is whether the traces contain reflection and backtracking.

Backtrack count at test time correlates with score at r = 0.82–0.85. Teaching the model to doubt itself is what makes RL work.

03 — The build

The pipeline, and what changes

Same five stages. What moves between them is different, and two of them collapse almost entirely because our verifier is a physics engine rather than a string match.

04 — The hard part

Our actions are continuous

ASTRO searches discrete reasoning steps. A repair is (part, operation, axis, magnitude) — and the magnitude is a real number. Three things follow, and getting any of them wrong quietly produces degenerate traces.

1 · Uniqueness is per hypothesis, not per action string

ASTRO forbids two nodes carrying the same incorrect answer. Translated literally that forbids duplicate action strings — which is useless here, because TRANSLATE(P1,Y,-0.145) and TRANSLATE(P1,Y,-0.150) are the same hypothesis wearing two numbers. A trace that "explored" both would teach the model to re-probe a branch it had already refuted. So the unit is the discrete cell (part, op, axis), and the magnitude lives inside it.

2 · A refinement is not a backtrack

Walking down a refinement chain is continuation — the search has locked on and is tuning a number. Only a change of cell is a backtrack. This distinction does not exist in ASTRO, because a math step has no parameter to tune, and it is the whole reason for the third level of the tree.

3 · The sign belongs to the magnitude

A wrongly-signed probe makes the error worse, so trying the opposite sign is a refinement inside the cell, never a new branch. This one is not academic — see below.

Measured. Probing ROTATE(part, A, +20) once per axis and never trying the other sign left rotate faults at 3/10. In every failure, no probe ever beat the broken object, so the lock-on threshold never fired and refinement never started. Adding the flip took rotate to 9/10.
05 — A finding

The trap in our own prompt

Building the expert surfaced something about the environment that applies to the models too.

deviation_mm is mean per-vertex displacement. So a translation along the mis-scaled axis produces a larger error drop than the correct SCALE probe does. The prompt's own instruction — "the moment any probe cuts the error by half or more, the search is OVER" — therefore locks onto the wrong hypothesis and refines into a dead end.

Why this matters beyond the expert. Refining the top three cells instead of committing to the first took scale from 6/10 to 7/10, and it is the more faithful reading of ASTRO anyway — its MCTS explores several branches. But the same trap is in the prompt the models read, and scale is their weakest fault type too (2/10 text, 4/10 image). That is testable as a prompt change on its own, with no training involved.

Every turn is an independent training pair. loop_qwen runs window3, which is a stateless single-message call — the probe log is re-rendered into the prompt each turn. So a six-turn trace is six (system, user) → assistant examples, with no multi-turn masking and no conversation collator.

The prompts are not written by hand. $history, $untried and $targetable are computed from env.history at call time, so the builder steps a real FridgeRepairEnv and calls the agent's own prompt methods. Prompt parity with evaluation is structural rather than asserted.

Why the inversion happens

Scale faults are readable. The mis-sized door's ratio to its sibling sits right in the geometry block, so an answer-shaped trace teaches "read the ratio, scale by it" — and the direct arm does exactly that, fast (2.7 sims per solve).

Translate and rotate faults must be measured. Their magnitudes exist only in probe feedback — the error in millimetres, the sign flip, the secant step. Clean traces show the final answer with the measurement process amputated: the direct arm names the right repair type almost perfectly (98% type accuracy) and still misses, because its magnitudes are off and it cannot recover (27%). The astro traces teach the measuring itself — and there search wins 5–6×.

The search prior pays exactly where the answer is not readable from the state. This is ASTRO's Table-4 claim, replicated at +42 points instead of their +4 — with a decomposition the math benchmarks could not show.

What's next

A combined arm — the two profiles are complementary (100/82/52 vs 16/19/74), so traces that include the direct arm's ratio-read scale repairs should clear both. And RL (Stage 3): ASTRO's thesis is that RL amplifies a search prior — this model now demonstrably has one, and the reward function is already the simulator.
